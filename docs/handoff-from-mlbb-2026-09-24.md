## 3. 移すときの要点

### 3-1. 色は変数の写し替えで持つ（部品のクラス名は変えない）

Tailwind 4 の既定色（slate、white、rose など）は、CSS に `var(--color-slate-500)` の形で出る。
`@theme {}` で値を定義し直せば、クラス名はそのままで全ページの色が変わる。
MLBB はこの仕組みで、明るい配色の「明るい地＋濃い文字」を「暗い地＋明るい文字」へ段ごとに写した。

- `bg-white` はカードの地（暗い色）になる。`text-white` は「濃い塗りの上の文字」なので、こちらも暗い色になる
- slate の 50〜300 が面と線、500〜900 が文字。500 は補足、700 は本文、900 は見出し
- 実物は MLBB の `src/app/globals.css` の 1〜190 行。値の検算は `scratch/dark_palette_0924.mjs`
- `dark:` 変種は使わない。HoK の検査16も再発を見張っている

HoK で先に手を入れるところ:

- **`brand` と `jade` が `@theme inline` の中にある。** inline の値はクラスに直に埋め込まれるので、
  あとから一部の面だけ元の色に戻せない。MLBB も brand・gold・jade を `@theme {}` へ移した
- 色の使用数（2026-09-24、src の tsx/ts）は slate 1222、brand 216、amber 99、emerald 91、rose 60、blue 52。
  この6系統を写せば、ほぼ全体が変わる
- rose の過半はアルカナの赤スロットの色（globals.css 冒頭のコメント）。暗い地でも赤スロットに見えるかを画面で見る
- `:root` に `color-scheme: dark` を置く。標準のスクロールバーや入力欄も暗く描かれる
- `theme-color`（`[locale]/layout.tsx`）、`public/manifest*.json` の2色、OGP 画像の `BG`（`src/lib/ogImage.tsx`）を
  新しい地の色にそろえる。ここが割れるとアドレスバーとページの間に段差が出る（AGENTS.md「地は白磁」の節）

写し替えで壊れるもの（MLBB で実際に踏んだ）:

1. `bg-slate-900 text-white` の「墨の選択中」は、白く光るピルになる。
   選択中は差し色の線と淡い塗りに変える（MLBB は `border-gold-300 bg-gold-50 text-gold-700`）
2. 暗幕の `bg-slate-900/60` は白い膜になる。`bg-black/60` にする
3. もともと暗い面は、写し替えると明るくなってしまう。
   その要素に `data-surface="dark"` を付け、`[data-surface='dark']` の中だけ元の明るい配色の値に戻す（MLBB の globals.css 143 行〜）。
   HoK では PWA の追加案内（`PwaInstallBanner.tsx` の `bg-slate-900` など6か所）が当たる。サイドバーは白い地なので要らない
4. インラインの `style` や SVG に直に書いた色は写し替わらない。HoK の `style` 内の色は 0 件だったが、SVG の `fill` と画像は目で見る
5. `shadow-*` は暗い地ではほぼ見えない。区切りは線か淡い光で出す

### 3-2. 絞り込みはアイコン付きのプルダウンにする

MLBB の `src/components/common/Dropdown.tsx`（255 行）を持ってきてよい。単一選択と複数選択の両方を持つ。
既定値から変えたときは、枠が差し色になる。

作り込んだところ:

- ボタンは高さ 44px（`h-11`）。候補の行も `min-h-11` で、候補の文字は 16px
- 画面の端では右寄せや上開きに切り替わる。下にタブバーがあるので、下端は 76px 空けて判定している
- 矢印・Home/End・Enter/Space・Esc・Tab で操作でき、外を押すと閉じる
- 複数選択で同じ瞬間に2回押されると、1回目が消えた。最新の値を ref に持たせて直してある

使い分けの目安:

- 画面の主軸で、それぞれ URL を持つもの … タブのまま残す（MLBB の Tier表のレーン）
- 2〜3択の並べ替え … ボタンを横に並べた切り替え
- それ以外（ロール・レーン・難易度・4択以上の並べ替え） … プルダウン。スマホでは2列に並べる

HoK で当てはまる場所:

- ヒーロー一覧（`HeroesListClient.tsx`）… 検索・ロール・レーン・難易度・サブロール・並べ替えの6つがある。チップの列がいちばん多く、効果も大きい

### 3-4. Tier表は顔アイコンの格子にする

MLBB の `src/components/tier-list/TierListClient.tsx`。

- 列はスマホで4、広くなるにつれ 6・8・10。列の数は `matchMedia` と `useSyncExternalStore` で読む（`useColumns()`）
- 顔を押すと、その行の末尾に詳細の枠（勝率・採用率・BAN率と、ヒーローのページへのボタン）が入る。`col-span-full` の1枠
- 顔は `<a>` のまま。普通に押したときだけ `preventDefault` で開閉する。Ctrl＋クリックや新しいタブでは詳細ページへ行く。`aria-expanded` を付ける
- 最上位の段は、差し色の枠と淡い光で分ける

HoK の Tier表には共有モード（`shareMode`）がある。画像にして貼られる画面なので、暗い地で読めるかを必ず見ること。

### 3-5. 横に流れる表は、スマホで1件2行にする

MLBB の統計（`src/components/stats/StatsRankingClient.tsx`）とロール別（`src/components/heroes/HeroGroupView.tsx`）が見本。
行を CSS grid にして、スマホでは2行に組む。md 以上は `md:contents` で表の列に戻す。同じ HTML で両方を出せる。

比較表（`CompareClient.tsx`）で踏んだことがある。スマホで見出しの列を隠すのに `max-md:sr-only` を使ったら、列の幅が残った。
`max-md:hidden` に変え、代わりにスマホ用のラベル行を置いた（読み上げからは外していない）。

### 3-6. 共通の見た目

`globals.css` の末尾に2つのクラスを足した。

- `.page-hero` … ページ冒頭の帯。淡い放射状の光を2つ重ねる
- `.section-title` … 節の見出し。左に差し色の縦線が付く

ページ内の節へ飛ぶチップの列（MLBB の `SectionNav.tsx`）は、右端を CSS の mask でぼかした。続きがあると分かる。JavaScript は使っていない。

### 3-7. 文字は 14px 未満を使わない

運営者の方針は「文字を小さくしない。補足でも text-sm まで」。
MLBB は `text-xs` と `text-[9px]` を全廃し、`scripts/audit.mjs` の上限を 0 にした。

- HoK には現在 `text-xs` が 132 件、`text-[8〜11px]` が 208 件ある（2026-09-24）
- AGENTS.md は `text-[8px]` をふりがな（`<rt>`）に、`text-[9px]` を固定幅のマスに認めている。
  ふりがなは本文との比で決まるので、例外として残してよいか運営者に聞く。マスの文字は、マスのほうを広げて 14px にする
- 入力欄はスマホで 16px にする。iPhone の Safari は、16px 未満の欄を押すと画面を拡大して戻さない。
  MLBB は各欄を `text-base md:text-sm` にした。ワイリフは globals.css の1規則で一括して止めている（`@media (max-width: 767.98px)` の節）。
  HoK の globals.css にはまだ無い

### 3-8. 外枠

- AppBar … サイト名の横に「非公式」の札（14px、差し色の枠）
- TabBar … 選択中のタブは差し色の文字と上端の線。メニューの暗幕は `bg-black/60`。ラベルは省略せず `leading-tight` で折り返す
- サイドバー … 選択中は差し色の淡い塗りと輪郭（MLBB のサイドバーは紺の地だったので `data-surface="dark"` を付けたが、HoK は白い地なので写し替えに任せてよい）
- 横断検索 … 暗幕を `bg-black/60` に、選択中の行を差し色に。入力欄は 16px

## 4. HoK の決まりとぶつかるところ

AGENTS.md の「🎨 デザイン規約（玉璽）」は、明るい地を前提に書かれている。試作が通ったら、同じ作業の中で書き直す。

- 地は白磁 `#fbfaf7` … 新しい地になる。文字色の下限の表も測り直す
- 「選ばれている」の塗りは墨 … 白く光るので使えない。
  選択中は金の線と淡い塗りにして、金の塗りは序列の最上位（Tier S）だけ、という役割の分け方は残せる
- 文字サイズ … 3-7 のとおり
- 検査16 の件数の上限（`text-slate-400` など）は、新しい配色で数え直す。MLBB の上限と理由は `scripts/audit.mjs` の `CEILINGS` にある

「骨格を変えるときは、古いHTMLを残り物として考える」の節も読むこと。
今回は全ページのクラスが変わるので、`@source inline(...)` で残す方式は量の面で成り立たない。
古いHTMLが新しいCSSと出会う経路（Service Worker、ブラウザや CDN のキャッシュ）を先に確かめ、対策を決めてから出す。

## 5. 確かめ方

MLBB の `scratch/` にある道具を写して使う。MLBB は静的書き出しなので、`out/` を 3012 番で配って測っていた。
HoK では `npm run build` のあと `npx next start -p <番号>` で立て、道具の中の URL を合わせる。

| 道具 | 測るもの |
|---|---|
| `mobile_audit_0924.mjs [幅]` | 横はみ出し、14px 未満の文字、押しにくい的、iPhone の拡大、固定帯の高さ、画面の枚数、横スクロールする表 |
| `contrast_render_0924.mjs [幅]` | 描画後の文字と、その下に見えている地の比。4.5:1 未満を出す |
| `page_shot_0924.mjs <名> <path> [幅] [手順]` | 1ページを撮る。スクロール・クリック・撮影の順を指定できる |
| `dark_palette_0924.mjs` | 配色案の段ごとの比 |

- 390px と 360px の両方で測る。MLBB では 360px のとき、スキル表とTier表のレーンのタブが枠の中で少し横に流れる状態が残った
- **英語のページも測る。** MLBB は日本語だけのサイトなので、英語で長くなるラベル（プルダウン、レーンの短い名前）は試していない
- 作業の前と後で同じ道具を回し、数の変化を報告に書く
- ボタンを文字で探して押すと、サイドバーにある同じ名前のリンクを拾うことがある（「スキル」で「バトルスキル」を押した）。`#id` の URL で飛ぶほうが確実

## 6. 進め方

MLBB と同じ順が安全。

1. ブランチを切る（MLBB は `design/dark-0924`）
2. 配色（globals.css）と、ヒーロー一覧かTier表の1枚を試作する。390px で撮り、地の色の案と一緒に運営者へ見せる
3. 承認をもらったら、ページの組ごとに1コミットで広げる
4. 全ページを描画して測り、細部を直す
5. `npx tsc --noEmit`・`npx eslint src`・`npm run audit`・`npm run build`・`npm run smoke` を通して報告する。push は運営者の指示を待つ

## 7. ほかに気をつけること

- MLBB は `src/` の一部が CRLF だった。複数行の置換は、LF にそろえて置換し、書き戻すときに CRLF へ戻した
- Bash のヒアドキュメントと `node -e` は、バックスラッシュとバッククォートを壊す。スクリプトは Write ツールで作ってから実行する
- 別件として、MLBB は同じ日に Next.js を 16.2.6 → 16.3.6 に上げた（`9fc3fea`）。npm audit の critical 1件を含む9件が5件に減り、型検査・監査・ビルドはそのまま通った。
  HoK はまだ 16.2.6。MLBB は静的書き出しなので実害が無かったが、HoK は静的書き出しではない。
  `npm audit` で当てはまるかを見て、作り直しとは別のコミットで先に上げておくとよい
- MLBB で同時に直した英語の混入（スキル表の「(Mana)」など）や用語の統一は、MLBB の掲載文の話なので、この作業には含まない
